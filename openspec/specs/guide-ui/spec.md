# guide-ui Specification

## Purpose

사이트 전반의 시각 언어와 체크리스트 UI의 상호작용 계약을 정의한다. 레퍼런스 사이트의 채도 높은 프로덕트 UI를 레포의 잉크 단색 에디토리얼 시각 언어로 번역하는 규칙, 그리고 그 결과가 접근 가능해야 한다는 요구를 담는다.

## Requirements

### Requirement: 시각 언어 준수

시스템의 모든 화면은 레포 루트 `design.md`가 정의한 시각 언어를 따라야 한다(SHALL). 구체적으로:

- 디스플레이 헤드라인은 weight 300으로 렌더되어야 하며, 볼드로 표시되어서는 안 된다(MUST NOT)
- 모든 CTA 버튼과 배지는 pill 형태(완전히 둥근 모서리)여야 한다(MUST)
- 주 액션 색상은 웜 니어블랙 잉크 계열 하나여야 하며, 채도 높은 브랜드 액션 컬러를 도입해서는 안 된다(MUST NOT)
- 파스텔 색상은 부드러운 방사형 분위기 장식으로만 등장해야 하며, 버튼 채움·텍스트 색·카드 배경 채움으로 사용해서는 안 된다(MUST NOT)
- 그림자는 단일 단계만 사용해야 한다(SHALL)

#### Scenario: 헤드라인이 볼드로 렌더되지 않는다

- **WHEN** 랜딩·학습 경로·가이드 상세의 헤드라인을 확인한다
- **THEN** 모든 디스플레이 헤드라인이 weight 300으로 렌더된다

#### Scenario: 채도 높은 액션 컬러가 없다

- **WHEN** 사이트의 모든 버튼과 배지를 확인한다
- **THEN** 채움 색상은 잉크 계열 또는 중성 회색 계열뿐이며, 파스텔 색은 어떤 컨트롤의 채움에도 사용되지 않는다

#### Scenario: 장식 요소가 상호작용을 방해하지 않는다

- **WHEN** 파스텔 분위기 장식이 놓인 영역에서 컨트롤을 클릭한다
- **THEN** 장식은 포인터 이벤트를 가로채지 않고, 보조 기술에도 노출되지 않는다

### Requirement: 색에 의존하지 않는 상태 구분

시스템은 완료·미완료 상태를 색상만으로 구분해서는 안 된다(MUST NOT). 형태, 아이콘, 굵기 등 색 이외의 신호를 함께 사용해야 한다(SHALL).

#### Scenario: 완료와 미완료가 형태로 구분된다

- **WHEN** 한 챕터 안에 완료된 스텝과 미완료 스텝이 함께 있다
- **THEN** 미완료는 비어 있는 링으로, 완료는 채워진 원과 체크 아이콘으로 표시되어 색 인지 없이도 구분된다

### Requirement: 명령어 복사

시스템은 표시된 각 터미널 명령어에 대해 클립보드 복사 컨트롤을 제공해야 한다(SHALL). 복사가 성공하면 학습자에게 시각적 확인을 제공해야 하며(MUST), 그 확인은 일정 시간 후 원래 상태로 돌아가야 한다(SHALL). 클립보드 접근이 실패하면 오류로 화면을 중단시켜서는 안 된다(MUST NOT).

#### Scenario: 명령어를 복사한다

- **WHEN** 학습자가 명령어의 복사 컨트롤을 활성화한다
- **THEN** 표시된 명령어 문자열과 정확히 일치하는 내용이 클립보드에 들어가고, 컨트롤이 성공 상태로 바뀐 뒤 잠시 후 원래대로 돌아온다

#### Scenario: 클립보드 접근이 거부된다

- **WHEN** 브라우저가 클립보드 접근을 거부한 상태에서 복사를 시도한다
- **THEN** 페이지는 정상 동작을 유지하고 사용자에게 실패가 조용히 성공으로 보이지 않는다

### Requirement: 키보드 접근성

모든 상호작용 요소는 키보드만으로 도달하고 조작할 수 있어야 한다(SHALL). 포커스를 받은 요소는 항상 눈에 보이는 포커스 표시를 가져야 한다(MUST).

#### Scenario: 키보드만으로 전체를 순회한다

- **WHEN** 학습자가 마우스 없이 Tab만으로 가이드 상세 페이지를 처음부터 끝까지 이동한다
- **THEN** 챕터 펼치기, 스텝 펼치기, 완료 표시, 명령어 복사, 링크에 모두 도달할 수 있고 각 단계에서 포커스 위치가 보인다

#### Scenario: 완료 표시를 키보드로 토글한다

- **WHEN** 완료 표시 컨트롤에 포커스가 있는 상태에서 Space 또는 Enter를 누른다
- **THEN** 완료 상태가 토글된다

#### Scenario: 접힌 영역의 요소는 포커스를 받지 않는다

- **WHEN** 챕터나 스텝이 접힌 상태에서 Tab으로 이동한다
- **THEN** 접힌 영역 안의 컨트롤에는 포커스가 가지 않는다

### Requirement: 보조 기술 노출

완료 표시 컨트롤은 보조 기술에 체크 가능한 컨트롤로 노출되고 현재 상태를 전달해야 한다(SHALL). 진행률 집계의 변화는 스크린리더에 알려져야 한다(MUST). 순수 장식 요소는 보조 기술에서 제외되어야 한다(MUST).

#### Scenario: 스크린리더가 완료 상태를 읽는다

- **WHEN** 스크린리더 사용자가 완료 표시 컨트롤에 도달한다
- **THEN** 어떤 스텝에 대한 컨트롤인지와 현재 완료 여부를 함께 전달받는다

#### Scenario: 진행률 변화가 알려진다

- **WHEN** 스크린리더 사용자가 스텝을 완료 표시한다
- **THEN** 갱신된 진행률이 방해 없이 알려진다

### Requirement: 반응형 레이아웃

시스템은 모바일·태블릿·데스크톱 폭에서 모두 사용 가능해야 한다(SHALL). 어떤 폭에서도 가로 스크롤이 발생해서는 안 된다(MUST NOT). 터치 대상은 충분한 크기를 확보해야 한다(MUST).

#### Scenario: 좁은 화면에서 가로 스크롤이 없다

- **WHEN** 375px 폭에서 모든 페이지를 확인한다
- **THEN** 가로 스크롤이 발생하지 않고 헤드라인 크기가 해당 폭에 맞게 축소된다

#### Scenario: 긴 명령어가 레이아웃을 밀어내지 않는다

- **WHEN** 화면 폭보다 긴 명령어가 좁은 화면에 표시된다
- **THEN** 명령어는 자체 영역 안에서만 스크롤되거나 줄바꿈되고 페이지 전체를 가로로 밀지 않는다

### Requirement: 모션 축소 존중

사용자가 운영체제에서 모션 축소를 선호한다고 설정한 경우, 시스템은 펼침·접힘 애니메이션을 제거해야 한다(SHALL).

#### Scenario: 모션 축소 설정에서 애니메이션이 없다

- **WHEN** 모션 축소를 선호하는 사용자가 챕터를 펼친다
- **THEN** 내용이 애니메이션 없이 즉시 나타난다
