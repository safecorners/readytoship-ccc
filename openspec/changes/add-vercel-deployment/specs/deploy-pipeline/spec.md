## Purpose

저장소의 변경이 배포에 도달하는 경로를 정의한다. 프로덕션과 프리뷰 배포가 각각 언제 일어나는지, 그리고 검증을 통과하지 못한 변경이 프로덕션에 닿지 못하게 막는 규칙을 담는다.

## ADDED Requirements

### Requirement: 프로덕션 자동 배포

기본 브랜치에 변경이 병합되면 시스템은 프로덕션에 자동으로 배포해야 한다(SHALL). 배포를 위해 사람이 명령을 실행하거나 대시보드를 조작하는 절차를 요구해서는 안 된다(MUST NOT).

프로덕션 주소는 고정되어야 하며(SHALL), 배포마다 바뀌어서는 안 된다(MUST NOT).

#### Scenario: 병합이 프로덕션에 반영된다

- **WHEN** 변경이 기본 브랜치에 병합된다
- **THEN** 사람의 추가 조작 없이 프로덕션 배포가 시작되고, 완료 후 고정된 프로덕션 주소에서 그 변경이 보인다

#### Scenario: 배포에 수동 절차가 없다

- **WHEN** 기여자가 변경을 병합하는 것 외에 아무 일도 하지 않는다
- **THEN** 프로덕션에 반영되며, 별도의 배포 명령이나 승인 단계를 밟도록 요구받지 않는다

### Requirement: 브랜치 프리뷰 배포

기본 브랜치가 아닌 브랜치에 변경이 올라오면 시스템은 그 브랜치만의 주소로 배포해야 한다(SHALL). 프리뷰 배포는 프로덕션 주소의 내용을 바꿔서는 안 된다(MUST NOT).

프리뷰 주소는 해당 변경의 검토 창구에서 확인할 수 있어야 한다(SHALL).

프리뷰 열람은 권한 있는 검토자로 제한되어야 하며(SHALL), 검색 엔진에 노출되어서는 안 된다(MUST NOT). 아직 병합되지 않은 내용이 공개 주소로 돌아다니지 않게 하려는 것이다.

#### Scenario: 권한 있는 검토자가 병합 전에 실제 화면을 확인한다

- **WHEN** 기여자가 브랜치를 push하고, 권한 있는 검토자가 검토 창구의 프리뷰 주소를 연다
- **THEN** 그 브랜치의 내용이 반영된 화면이 보인다

#### Scenario: 권한 없는 접근은 내용을 보지 못한다

- **WHEN** 인증되지 않은 방문자가 프리뷰 주소를 연다
- **THEN** 페이지 내용이 전달되지 않고 인증 절차로 안내된다

#### Scenario: 프리뷰가 프로덕션을 건드리지 않는다

- **WHEN** 프리뷰 배포가 완료된다
- **THEN** 프로덕션 주소는 여전히 마지막으로 병합된 내용을 보여 준다

### Requirement: 병합 게이트

시스템은 검증을 통과하지 못한 변경이 기본 브랜치에 병합되는 것을 막아야 한다(MUST NOT allow). 검증은 최소한 다음 둘을 포함한다.

- **빌드** — 프로덕션 빌드가 성공해야 한다. 콘텐츠 검증이 빌드 시점에 실행되므로(`guide-content` — 콘텐츠 검증) 잘못된 튜토리얼 콘텐츠는 여기서 걸린다.
- **정적 분석** — 린트가 통과해야 한다. 프로덕션 빌드가 린트를 포함하지 않으므로 별도의 검사가 필요하다.

검증 결과는 병합 여부를 결정하는 자리에 드러나야 하며(SHALL), 기여자가 결과를 찾아 나서게 해서는 안 된다(MUST NOT).

#### Scenario: 빌드가 깨진 변경은 병합되지 않는다

- **WHEN** 컴파일에 실패하는 변경이 검토에 올라온다
- **THEN** 빌드 검증이 실패로 표시되고 병합이 허용되지 않는다

#### Scenario: 잘못된 콘텐츠는 프로덕션에 닿지 못한다

- **WHEN** 스텝 식별자가 중복된 가이드 변경이 검토에 올라온다
- **THEN** 콘텐츠 검증이 빌드를 실패시키고, 그 변경은 병합되지 않는다

#### Scenario: 린트 오류가 병합을 막는다

- **WHEN** 빌드는 통과하지만 린트 규칙을 위반한 변경이 검토에 올라온다
- **THEN** 린트 검증이 실패로 표시되고 병합이 허용되지 않는다

#### Scenario: 검증을 모두 통과하면 병합할 수 있다

- **WHEN** 빌드와 린트가 모두 통과한 변경이 검토에 올라온다
- **THEN** 병합이 허용되고, 병합 즉시 프로덕션 배포가 시작된다

### Requirement: 배포 규칙의 문서화

배포가 언제 어디로 일어나는지, 그리고 병합을 막는 검증이 무엇인지는 저장소에서 읽을 수 있어야 한다(SHALL). 이 정보가 배포 플랫폼의 설정 화면에만 존재해서는 안 된다(MUST NOT).

#### Scenario: 저장소만 보고 배포 방식을 안다

- **WHEN** 처음 이 저장소를 받은 사람이 배포가 어떻게 되는지 알아본다
- **THEN** 프로덕션 주소, 배포가 일어나는 시점, 병합에 필요한 검증을 저장소 문서에서 확인할 수 있다
